Hodge renderer asset handoff

Runtime files: renderer.js and meshes/. The mesher.js source is only used offline. Catalogue pages load the common saved-mesh format. Home retains the original quantized 256^3 asset at the owner’s request.

API:
  const renderer = HodgeRenderer.create(canvas, {
    onStatus({state,message,meta}) {},
    onModeChange(mode) {}, // catches Escape as well as setMode calls
    // assetBase: '/assets/' // optional; defaults to renderer.js directory
  });
  await renderer.setCase(record);
  renderer.setMode('free');
  renderer.setMode('parallax'); // resets exact home pose immediately
  renderer.destroy();

create() is synchronous and does not select an initial case automatically.
Home uses its original contact46006 asset, plane seed 245646, yaw .710, pitch .455, distance 3.22, and center [0,0,0]. See slices/home.json. Its catalogue card keeps the refreshed view.

Each render.mesh is relative to assetBase, e.g. meshes/slice-<digest>.json.
A manifest stores compressed vertices/indices paths and numeric geometry metadata.
Each render.camera contains yaw, pitch, distance, and center. This saved pose drives
both parallax and reset after free camera. Rendering uses 88^3 sampling, or 112^3
for the two polarized-contact sections. The title page retains its original baked-asset loader.

All 61 records have fresh planes and cameras from the 2026-10-14 presentation pass.
Identical-F cards share a plane. Candidate views favor visible normal variation,
projected spread, and little clipping; these are starting points for manual review.

D is highlighted when certificateAvailable:true or evidenceKind:'explicit-certificate'. Formal proof status is independent.
Default mode is parallax. Box is fixed to [-10,10]^3, x-ray on at reach 2.0, six depth-peeling layers.
Every slice dissolves by transparent coverage from box distance 8.25 to 9.92.
Previously only the old home used this fade; generic meshes darkened but stayed opaque.
Free controls: screen-relative quaternion trackball; pan with right/shift drag; wheel/pinch zoom; R or double-click reset; Escape returns.
The renderer draws no UI or controls. Parent UI is responsible for hiding/revealing all challenge content in free mode.

The visible surface is a numerical two-dimensional real section of the complex sextic fourfold:
  z = diag(1 or i) B u, u in S^3,
where the stored 6x4 real planeMatrix has orthonormal columns and F restricts to a scalar-real polynomial.
Stereographic coordinates are sampled in the fixed box [-10,10]^3. This shows the antipodal sphere cover of the projective slice.
No numerical mesh is a proof of topology, smoothness or certificate validity.

Validation:
- Every refreshed mesh passes finite attributes, unit normals, normalized bounds, index bounds, and maximum sampling-cell edge checks.
- Original evaluator and extracted evaluator matched exactly at sampled points across five distinct corpus formulas.
- Generic sparse Fermat meshing matched the original built-in evaluator vertex positions.
- Non-real phase restrictions are rejected rather than silently drawing Re(F)=0.
- Dense degree-48 D uses a compact evaluator from its source record; compared with all 4,900 terms, maximum relative discrepancy was 1.6e-13 at 24 sample points.
- Two polarized-contact cases use ordinary real coordinates; their initially chosen imaginary-Y slice had no usable sign change.
- The shared mesher now refines edge roots to convergence and computes differential normals at those roots. The old case-58 regression reduced wrong-sign normals from 11 to zero and wrongly facing triangles from 84 to zero; normalized pre-Float32 root residual fell from about 1.3e-5 to 7.4e-14. Narrow joins can still be smaller than a fixed grid resolves.

Offline rebuild:
  node scripts/rebuild-meshes.cjs data/index.json /tmp/hodge-mesh-rebuild 88
The offline mesher accepts only an existing saved orthonormal planeMatrix. It contains no random-plane generator. The website itself loads saved meshes only; it has no worker fallback or plane-generation path. The new output directory includes a slice-settings.json manifest for review before replacing any shipped assets.

Offline selection of new planes and views (never runs in the browser):
  node scripts/refresh-slices.cjs . /tmp/hodge-slice-refresh
The output is separate for review. To replay the saved selection, copy
slices/plane-selections.json into the output directory and use --bake-only.
The refresh cache identity includes the mesher SHA256. Read slices/curation.md
for the candidate scoring, integration steps, and numerical limitations.
